# 問題と解説の作成・保守

## 原本と派生データ

IPAの年度別過去問題ページからPM午前Ⅱの問題・解答だけを取得する。原本PDFは編集せず、年度別の原本・OCR・抽出作業資料はGit管理から除外する。新規チェックアウトでは `python scripts/fetch-sources.py` で取得し、ハッシュ一致を必須とする。取得URL・取得日・SHA-256を `sources/manifest.json` に記録する。年度の呼称を参照元SAから流用しない。

画像の切り出しは参照元 `rabut001/system-arch-training` の処理を参考に、原本のテキスト座標が取得できる場合は問番号を利用する。画像のみのPDFなどは明示的な切り出し座標で補う。自動判定できないものを推測のまま公開しない。

照合済みの記録はOCR全文を除いて `sources/index.json` に保存する。`--recorded` でOCRなしに画像を再作成できる。問番号ごとにページと領域を記録し、問題文・全選択肢・図表・脚注が含まれることを原本と照合する。問が複数ページの場合は全領域を含める。正解は解答PDFから抽出し、1～25が一度ずつ存在することを確認する。公式に不成立の問題は注記を照合し、正解を捏造せずnullとinvalidReasonを記録する。年度一覧と問題JSONのexcludedQuestionNosにも対象番号を記録し、採点対象から除外する。平成28年度春期問2が該当する。

## 解説の基準

- 全問、正解の根拠を書く。問題や肢の言い換えだけで終わらせない。
- 知識問題は各誤答肢の誤りや適用対象を簡潔に説明する。
- 用語名だけの肢はその意味も書く。計算問題は式・代入・結果を示す。最大／最小を選ぶ場合は比較を示す。
- 規格・制度は出題時点に合わせる。現行との差が学習に影響する場合は注記する。必要な事実は一次資料で確認し、根拠URLを作業記録に残す。
- 実行時のAI生成は行わず、確認した解説をJSONへ保存する。公式正解と独自解説を区別する。

補助テキストは原文の逐語的な転記ではなく学習用の要約。数値・肢の対応・前提条件を原本と照合し、原文や図表は画像を見る旨を表示する。類似・再出題を参考にする場合も、当該年度の原本と全四肢を確認する。肢の入替えや文言の差をそのまま流用しない。参照元リポジトリの問題・解説を利用した問は、案件の照合記録に参照先を残す。

## 作成と照合を分ける

初回は令和7年度25問で画面・抽出・解説の粒度を合わせ、利用者レビュー後に残り16回へ展開する。

案件配下の `content-checks.json` で問ごとに、抽出、正解照合、解説作成、画像照合、解説照合の結果と実施内容を記録する。作成と照合は別の工程にする。実施していない確認を完了としない。自動検証は件数・型・画像の存在・公式正解との一致を担い、画像や解説の意味の確認を代替しない。

## 公開と訂正

出典は年度・期・試験区分・時間区分・問番号と原本リンク。独自解説には「IPAの公式解説ではありません」と記載する。IPAの留意点は https://www.ipa.go.jp/shiken/faq.html を確認する。

訂正は新しい改修案件として記録し、正本と問題JSONを更新し、関連する画像・正解・解説を再照合する。保存済み回答は正解を保存せず、問題データから採点を再計算するため、正解訂正が画面へ反映される。
