# プロジェクトマネージャ 午前Ⅱ 演習：現在の仕様

合意日：2026-10-21。小規模な静的Webアプリとし、React・TypeScript・Vite・通常のCSSを用いる。

## 収録範囲

平成21年度～令和7年度のPM午前Ⅱ17回・425問。平成23年度は特別試験、令和2年度は10月試験。平成21～22年度と平成24～31年度は春期、令和3～7年度は秋期。まず令和7年度25問をレビュー用に作成する。

2026年度の名称は科目A-2。アプリでは午前Ⅱと現名称を併記する。出典は当時の名称を保持する。午前Ⅰ・午後・非公開問題は対象に含めない。

## 画面と操作

- 年度一覧 → 共通の演習画面。年度は新しい順。各回に選択済み件数、確認済み件数、続きからの案内を表示する。
- オフホワイトと青を基調とし、参照元の四択、問題番号、正誤、チェックの考え方を継承する。
- 問題は1問ずつの原本画像。拡大表示を用意する。スマホでは縦のページスクロールを基本とし、問題番号は開閉できる。PCでは十分な幅がある場合に問題と回答・解説を左右に表示する。
- PCの未確認の回答欄は問題を読み進めても上部に残す。長い問題を読み終えてから回答する際に画面上部まで戻る必要をなくす。
- ア～エを選択し「結果を確認」で正誤、正答、解説を表示する。確認前は選び直せる。確認後は固定する。
- スマホで個別に結果を確認したときは、画面内の解説の先頭へ移動する。保存済みの問題を開き直した場合や問題番号で移動した場合は、問題の先頭から表示する。
- 前後、問題番号で移動する。各回の最後にいた問を復元する。問の切替時は問題の先頭に戻る。
- 一括採点は確認ダイアログの後、選択済み・未確認だけを確定する。未回答は採点せず、正解率の分母に含めない。
- チェックは回答状態と独立。どの状態でも付け外しできる。
- 同じ年度内で「すべて／未回答／誤答／チェック済み」を絞り込み、該当する問題番号と前後移動に適用する。未回答は選択そのものがない問。選択済み未確認と区別する。絞り込み中に該当から外れた現在の問も、その表示は維持する。対象がゼロなら案内を出し、すべてへ戻れる。絞り込みは解き直しモードではない。
- 回答クリアは確認ダイアログを経て当該年度だけの選択と確定状態を消し、問1に戻す。チェックは残し、絞り込みはすべてへ戻す。
- 原本の問題文は画像表示。補助テキストは設問・選択肢の学習用の要約であり、逐語的な転記ではないと明記する。図表・原文・厳密な条件は原本画像で確認できる。
- ボタンの押下領域、フォーカス表示、色以外の状態表示、ダイアログのフォーカス移動と復帰を確認する。
- 各問に年度・期・試験区分・午前Ⅱ・問番号・IPA原本へのリンクを表示する。解説に「IPAの公式解説ではありません」と表示する。

## 保存とデータ

- ログインなし。localStorageのみ。端末・ブラウザ間の同期はしない。
- キーは `pm-am2:v1:<exam-id>`。形式のバージョン、現在問、選択、確認状態、チェックを保存する。正解率は問題データと保存済み回答から再計算する。
- 破損したデータは無効な部分を除去して復元する。保存が使えない場合も演習を続け、画面で保存できないことを案内する。
- 問題JSON・画像は `public/data/<exam-id>/`。年度一覧は `public/data/exams.json` の一か所で管理する。
- JSONには番号、公式正解、画像、設問文、選択肢、図表の種類、段落に分けた独自解説を持つ。出典ページ・切り出し座標は作成記録に保存する。
- IPAが不成立とした平成28年度春期問2は、問題画像・解説と不成立の注記を収録する。正解はnull、invalidReasonに公式の理由を持たせる。選択・採点を行わず、正解率・未回答／誤答の集計対象から外す。チェックと閲覧は可能とする。全425問中の採点可能な問題は424問。
- 原本はローカルの `sources/<exam-id>/` に保存し、原本PDF・OCR全文・抽出作業ファイルはGit管理から除外する。URL・取得日・SHA-256を `sources/manifest.json`、最小限の切出し座標・正解メタデータを `sources/index.json` に記録する。これらと保守文書をソースとともに管理し、CIでは原本を一時取得して照合する。

## 配信・検証

- コンポーネントは公式LTSがあれば優先し、LTSがないものは保守中の安定版を採用する。系列の移行時は保守状況と互換性を確認し、検証後に手動で取り込む。
- Node.jsは最新のLTS系列を採用し、現行は24系とする。CIでは `.node-version` で指定したLTS系列と同梱npmを使う。次のLTSへの移行は手動で判断し、`@types/node` のメジャー更新はDependabotの自動提案から除外する。その他の依存は更新提案を継続し、React本体と型定義は同じグループでレビューする。
- CIのOSはUbuntu 24.04 LTSを明示する。Pythonは保守中の3.12系、PyMuPDFは固定版を使う。Pythonの保守期限を確認し、期限前に次の採用系列へ移行する。依存パッケージのバージョンとActionsのSHAを固定する。
- 公開先はGitHub Pages。Viteのbaseを公開リポジトリ名に合わせる。年度のURLはハッシュ形式とし、直リンク・再読込で404にならないようにする。画面は2種類なのでルーターライブラリを追加しない。
- GitHub Actionsでデータ検証、型検査、採点・保存テスト、ビルドを行ってからPagesへ公開する。
- 初回公開までに全425問の原本・正解・解説を照合する。試作時点で全回収録済みと表示しない。
